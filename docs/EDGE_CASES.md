# Known Edge Cases — ต่อโมดูล

เอกสารนี้รวบรวม **เคสขอบ (edge cases)** ที่เจ้าของแต่ละโมดูลควรรู้และทดสอบเป็นพิเศษ
ทุกเคสในนี้ตรวจสอบจากโค้ดจริง + ข้อมูลจริงใน `cis_database.db` (ไม่ใช่การเดา) บางเคส **เป็นบั๊กที่เจอจริงและแก้ไปแล้ว**
ระบุไว้เพื่อเป็นตัวอย่างว่าเคสแบบไหนควรระวัง

---

## 🐛 บั๊กที่เจอจริงระหว่างตรวจสอบ (แก้แล้ว — ใช้เป็นตัวอย่างเรียนรู้)

**อาการ:** หน้า Overview และ Fair Value ของหุ้น **HANA** และ **JMART** เคยโชว์ P/E เป็น `"nanx"` แทนที่จะเป็น `"-"`

**สาเหตุ:** ทั้งสองหุ้นมี **EPS ติดลบ** (HANA = -0.10, JMART = -0.11) ทำให้ `calculate_modules/fair_value.py`
คำนวณ `pe_ratio_now = None` ตามที่ตั้งใจ (เพราะ P/E ไม่มีความหมายเวลาบริษัทขาดทุน) แต่พอบันทึกผ่าน SQLite แล้วอ่านกลับมา
ค่า `None` กลายเป็น `NaN` (float) และโค้ด UI เดิมเขียน `{stock_info.get('pe_ratio','-')}x` ซึ่ง**ใช้ไม่ได้กับกรณีนี้**
เพราะ `.get(key, default)` จะคืน default ก็ต่อเมื่อ **ไม่มี key นั้นเลย** แต่ที่นี่ key มีอยู่ ค่าแค่เป็น `NaN` — ผลคือ f-string print ค่า `NaN` ออกมาเป็น `nanx`

**บทเรียนสำหรับทุกโมดูล:** ถ้าฟังก์ชันคำนวณของคุณมีโอกาส return `None` ให้ค่าตัวเลขไหนก็ตาม (เช่น หารด้วย 0 ไม่ได้, เงื่อนไขไม่เข้า)
**ห้ามแสดงผลด้วย `stock_info.get('key','-')` ตรงๆ** ให้ใช้ฟังก์ชัน `fmt_ratio()` / `safe()` ใน `common.py` แทนเสมอ
(ดูตัวอย่างการแก้จริงใน `common.py` และ `pages_content/fair_value.py`, `pages_content/overview.py`)

## ⚖️ Fair Value

| เคส | เกิดขึ้นได้ยังไง | โค้ดจัดการยังไงตอนนี้ | ควรทดสอบ |
|---|---|---|---|
| **EPS ติดลบ (บริษัทขาดทุน)** | ✅ **เกิดขึ้นจริงกับ HANA, JMART** ในข้อมูลปัจจุบัน | `pe_ratio` และ `pe_fair` จะ fallback เป็น `None` / `current_price*0.85` ตามลำดับ — **ต้องแสดงผลด้วย `fmt_ratio()` เท่านั้น** (ดูบั๊กด้านบน) | เทสต์ HANA และ JMART ทุกครั้งที่แก้หน้า Fair Value เพราะเป็น 2 หุ้นเดียวที่ชน edge case นี้จริง |
| Free Cash Flow ติดลบ | บริษัทลงทุนหนักกว่ากระแสเงินสดจากการดำเนินงาน | `dcf_equity` จะติดลบ → เงื่อนไข `if dcf_equity > 0` ไม่ผ่าน → fallback เป็น `current_price * 0.90` | ยังไม่เจอในข้อมูลปัจจุบัน |
| Total Equity ติดลบ หรือ 0 | ส่วนของผู้ถือหุ้นติดลบ/ศูนย์ | `pb_ratio_now` จะเป็น `None` (เงื่อนไข `book_value_per_share > 0`) — ใช้ `fmt_ratio()` แสดงผลถูกแล้ว | ยังไม่เจอในข้อมูลปัจจุบัน |
| DCF ให้ค่าที่ต่าง/ใกล้ราคาตลาดมาก | ปกติของทุกหุ้น | **ถูกหนีบ (clip) ไว้ที่ 65%-185% ของราคาตลาดเสมอโดยดีไซน์** — ดูรายละเอียดใน `DATA_FORMULA_AUDIT.md` หัวข้อ 2.1 | ไม่ใช่บั๊ก แต่เป็นพฤติกรรมที่ตั้งใจ ต้องเข้าใจไว้ก่อนแก้สูตร |

## ⏱️ Entry Timing

| เคส | เกิดขึ้นได้ยังไง | โค้ดจัดการยังไงตอนนี้ | ควรทดสอบ |
|---|---|---|---|
| หุ้นมีประวัติราคาน้อยกว่า 60 วัน | หุ้นเพิ่งเข้าตลาดใหม่ | `df_price_ticker.tail(60)` จะคืนแค่เท่าที่มี ไม่ error แต่ Resistance/Support จะคำนวณจากข้อมูลน้อยเกินไป ความน่าเชื่อถือต่ำ | ยังไม่เจอในข้อมูลปัจจุบัน (ทุกหุ้นมีข้อมูลตั้งแต่ต้นปี 2023) |
| ไม่มีข้อมูลราคาเลย (`df_price_ticker` ว่างเปล่า) | หุ้นใหม่ที่ยังไม่มีราคาบันทึก | **ยังไม่มีการป้องกัน** — `df_price_ticker.iloc[-1]` จะ `IndexError` | ถ้าจะเพิ่มหุ้นใหม่ ควรเทสต์ก่อนว่ามีราคาอย่างน้อย 1 แถว |
| RSI/MACD/ADX เป็นค่าว่างในบางวัน | ข้อมูล indicator วันแรกๆ ที่ยังคำนวณ moving average ไม่ครบ (เช่น EMA50 ต้องมี 50 วันก่อนหน้า) | `clean_float()` ใน `calculate_timing_module()` มี default กัน (rsi=50, macd=0, adx=20) แต่ใช้แค่ "วันล่าสุด" เท่านั้น ไม่กระทบ เพราะข้อมูลปัจจุบันมีมากพอ | ตรวจว่าวันล่าสุดของทุกหุ้นมีค่า indicator ไม่ว่างจริง |

## 🔮 AI Prediction

| เคส | เกิดขึ้นได้ยังไง | โค้ดจัดการยังไงตอนนี้ | ควรทดสอบ |
|---|---|---|---|
| ข้อมูล Train หรือ Test น้อยเกินไป (<50 หรือ <20 แถว) | หุ้นใหม่ที่มีประวัติราคาสั้น | **มีการป้องกันแล้ว** — return ค่า default ทันที (`ai_score=65, accuracy=75%` ฯลฯ) ไม่เทรนโมเดลจริง | ค่า fallback เหล่านี้เป็นค่ากลางๆ ที่ตั้งไว้ ไม่ใช่ผลจากโมเดลจริง — ถ้าเจอ ai_signal='ACCUMULATE' เหมือนกันหมดหลายหุ้น น่าจะเจอ edge case นี้ |
| Test set มีแค่ class เดียว (ราคาขึ้นทุกวันหรือลงทุกวันตลอดปี 2025) | เกิดขึ้นได้ทางทฤษฎีถ้าตลาดขาขึ้น/ลงแรงต่อเนื่อง | **มีการป้องกันแล้ว** — `roc_auc_score` มี `try/except` fallback เป็น 0.5 ถ้า `y_test.nunique() <= 1` | เช็ค `roc_auc` ของทุกหุ้น ถ้าเจอ 0.5 เป๊ะ อาจเป็นสัญญาณว่าชน edge case นี้ |
| `precision_score`/`recall_score`/`f1_score` เมื่อโมเดลไม่ทำนาย class บวกเลย | โมเดลระมัดระวังเกินไป ทำนาย "ไม่ขึ้น" ตลอด | มี `zero_division=0` กันไว้แล้วใน sklearn call ไม่ error แต่ precision/recall จะเป็น 0% ซึ่งถูกต้องตามจริง | ไม่ใช่บั๊ก แต่ควรเข้าใจว่า 0% ไม่ได้แปลว่าโค้ดพัง |
